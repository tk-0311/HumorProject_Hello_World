# Image-first caption choices

Creation requires a photo. Both apps generate nine distinct captions in one run through their configured prompt chain: three dry, three wholesome, and three absurd. There is no initial style dropdown. Dry / Wholesome / Absurd tabs display only three radio options at a time, with arrow-key and Home/End navigation. Switching tabs preserves the selected caption and shows its style and text near publication. **Generate new captions** clears the previous selection and generates all three styles again. The selected photo is retained on errors. Generating options does not publish anything.

Caption uploads in both apps and community profile-photo uploads now reuse exact image files within the signed-in user's folder and selected bucket. SHA-256 compares current bytes, including legacy uploads with random filenames; filenames themselves do not determine equality. Content-based paths and Storage's no-overwrite behavior prevent simultaneous identical uploads from creating extra files. Admin library uploads can check all owners within a bucket. No private cross-user reuse is exposed to community users. Edited, resized, or re-encoded files are distinct, and existing duplicate copies are retained. Failed draft/profile/publication saves keep the shared image for later admin cleanup so a concurrent successful save cannot lose its photo. Repeating caption generation still creates fresh caption options and consumes the normal allowance. Duplicate detection itself needs no migration.

Both caption forms now offer **Use an existing image**, and the profile-photo form offers the same choice for saved profile photos. Each picker displays at most 10 thumbnails, with **More images** and **Previous images** changing pages. The caption gallery contains published photos and the signed-in user's own available uploads/drafts, under normal Storage RLS. Saved selections are validated again on the server, including current bytes, MIME, size, and signature, and reuse their object path without uploading a copy. Hidden/private object IDs fail closed. Selecting a different photo clears old caption choices.

The applied migration [`20261028061633_saved_image_selection.sql`](supabase/migrations/20261028061633_saved_image_selection.sql) updates draft insertion/publication to accept authorized saved photos. Admin image replacement can atomically relink captions, drafts, profiles, and posts to another saved image from the same bucket; the original remains stored. Stable image-ID routes and explicit grants preserve legitimate linked-record access after replacement. A restrictive deletion policy protects shared references across owners. Catalog RPCs run as the caller under RLS; privileged helpers have fixed search paths and explicit role checks. No Storage bytes or metadata are changed through SQL.

The provider returns a `captions` object with three-string arrays named `dry`, `wholesome`, and `absurd`. Both servers validate group sizes, nonempty strings, the 280-character limit, and uniqueness across all nine captions, then flatten in that fixed order. Structured-output schemas enforce the group shape; application validation also enforces cardinality for providers with limited schema support.

Each community generation set is saved to one owner-private `caption_drafts` row with nine options, model, prompt-chain summary, stored image path, and draft style `mixed`. One saved set still counts once toward the existing daily allowance. Publication passes only the draft ID and global zero-based option index (0–8). The `publish_caption_choice` function authenticates the owner, locks the draft, derives the actual style from the stored index, inserts the selected caption into `ai_generations`, and records the published ID. Repeated publication returns that ID, preventing duplicate posts. Direct client updates cannot change or reset a draft's publication. Old three-option drafts retain their original style and index bounds. Admin publication similarly uses the selected option’s style, regardless of the currently visible tab.

The database migration `private_caption_choices_and_publication` has already been applied. Its source is recorded in `database/caption-choices.sql`; do not rerun its creation SQL. Storage cleanup now protects photos referenced by a private draft as well as published captions. Abandoned drafts remain private in storage/database; this update does not add a retention job.

The follow-up migration [`20261028020704_multi_style_caption_choices.sql`](supabase/migrations/20261028020704_multi_style_caption_choices.sql) is applied to the shared project. Deploy both apps together. No new dependencies or environment variables are required. Existing per-app prompt chains, model assignments, and provider credentials remain in use. Prompt Studio previews the same all-style contract used during generation; existing `{{style}}` placeholders expand to all three styles.
